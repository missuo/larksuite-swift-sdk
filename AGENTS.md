# AGENTS.md — larksuite-swift-sdk

Swift port of the official Feishu/Lark Node SDK. The reference implementation is
**https://github.com/larksuite/node-sdk** (currently generated from 1.76.0, commit
`b188be6`; clone it next to this repository to regenerate). CI regenerates from that commit
and fails if the checked-in generated code drifts. Progress and scope live in [PLAN.md](PLAN.md).

## Language

- Everything in this repository is written in English: code, comments, docs, commit messages,
  PLAN.md, skills.

## Hard rules

1. **node-sdk is the source of truth.** Every API and every runtime behaviour must match
   node-sdk exactly: HTTP method, path, query/body/path field names and types, multipart
   field names, response shapes, pagination rules, token caching and expiry margins,
   event parsing/flattening, signature and decryption algorithms, the long-connection
   protocol (frames, headers, ping/pong, fragments, acks, reconnect policy), and error codes.
   When in doubt, read the node-sdk source and copy its behaviour; do not "improve" it.
2. **Only the deviations listed below are allowed.** Any new deviation must be added to that
   list with a reason, in the same change.
3. **No API without strict tests.** Every new or changed API/behaviour ships with tests in the
   same change, and `swift test` must pass with zero failures before the work is considered
   done. Specifically:
   - Generated APIs: each method gets a generated parity test (`Tests/Lark<Module>Tests/
     <Module>ParityTests.swift`) asserting method, path, required query/body/multipart field
     names and decoding of a fully populated node-sdk response. Never hand-edit or delete
     these; fix the generator instead.
   - Runtime features (WS client, dispatchers, crypto, token manager, ...): tests must use
     **vectors produced by node-sdk itself** (run its code / its dependencies such as
     protobufjs and Node `crypto`, paste the output into the test with a comment saying how it
     was produced). Byte-for-byte equality is the bar for wire formats.
   - Cover failure paths too (bad signatures, malformed frames, business errors, retries).
4. **Generated code is never edited by hand.** Files starting with
   `// Code generated by Tools/codegen` (and `Package.swift`) are produced by
   `Tools/codegen`. Change `extract.js` / `generate.js` and regenerate. Hand-written helpers
   inside a generated module go in separate files without that header (they are preserved).
5. **Keep dependencies current and minimal.** Only `apple/swift-crypto` is allowed in
   `LarkCore`, declared as `"4.0.0"..<"6.0.0"` so the SDK can share one swift-crypto with
   packages still on 4.x (e.g. kwwk); everything used (`SHA256`, `Insecure.SHA1`,
   `AES._CBC`) exists in both majors, and CI resolves the latest 5.x. Adding a dependency needs a reason in PLAN.md. Re-check versions
   when touching `Package.swift` (`git ls-remote --tags <repo>`).
6. **Swift 6 strict concurrency, zero warnings.** Public types are `Sendable`; no
   `@unchecked Sendable` without a lock or actor protecting the state.
7. **Update PLAN.md and the skills** (`skills/`) in the same change as the feature.
8. **Never use real credentials in tests**, and never connect a long-connection client with
   a production app's credentials: the platform splits events between connections, which
   steals events from the live bot.

## Allowed deviations from node-sdk

| Area | node-sdk | Swift | Reason |
|---|---|---|---|
| Naming | `snake_case` payload objects, `{ path, params, data }` | camelCase properties; path params are labelled arguments, `params:` / `body:` structs; wire names unchanged | Idiomatic Swift; the wire format is identical |
| Business errors | returns the body when `code != 0` | throws `LarkError.api(LarkAPIError)` (with `code`, `msg`, `logId`, raw body) | Swift error handling; nothing is lost |
| Typed models | TypeScript types only (never validated at runtime) | `Codable` structs with lenient decoding; open string enums. Response/event types and every nested object type are all-optional; only top-level request `Query`/`Body` fields and path arguments keep node's required markers | Matches node at runtime: a missing or mismatched field becomes `nil` instead of failing or dropping the object, and one nested type serves both requests and responses |
| Event handlers | one flattened object | `LarkEvent` (whose `payload` is exactly node's flattened object) or a typed struct decoded from it | Type safety; same data |
| WS ack `biz_rt` | `startTime - endTime` (negative, a bug) | elapsed milliseconds (positive) | Field is a duration |
| Explicit tenant token | `withTenantToken` header is overwritten by the managed token unless `disableTokenCache` | an explicit token in `RequestOptions` always wins | Avoids silently ignoring caller input |
| Downloads | `writeFile(path)` / `getReadableStream()` | `LarkBinaryResponse` with `data`, `write(to:)`, `writeFile(_:)` | No Node streams in Swift |
| Aily class name | `Aily` | `AilyClient` | `Aily` is the generated models namespace |
| Aily failures | rejects with bare numbers; a transport error while polling a run hangs forever | throws `AilyExecStatus` (same values); polling transport errors are rethrown; task cancellation stops polling | Swift errors; avoid a never-ending task |
| Aily stream state | "output started" flag shared across iterations of the same iterable | per-iteration state | Independent iterations |
| Aily session records | stored under a `Symbol` key | stored in `LarkCache` as JSON under `aily-session-record`; non-scalar values skipped | `LarkCache` stores strings |
| `registerApp` cancellation | `AbortSignal` | task cancellation → `RegisterAppError(code: .abort)` (begin request still completes, as in node) | Swift concurrency |
| `registerApp` malformed begin response | TypeError / polls with `device_code=undefined` | throws `LarkError.decoding` | Fail fast instead of undefined behaviour |
| `registerApp` unknown addons keys | reports the first key in insertion order | reports the first key in sorted order | `JSONValue` objects are unordered |
| `registerApp` QR `source` param | `node-sdk` / `node-sdk/<source>` | same literal `node-sdk` (User-Agent is still `oapi-swift-sdk/...`) | The landing page sees the same value |
| Path parameters | inserted into the URL raw | percent-encoded per path segment | A raw value containing `/`, `?` or `#` produces a broken URL in node |
| User-Agent | `oapi-node-sdk/<version>`; sanitising works on UTF-16 units | `oapi-swift-sdk/<version>`; sanitising works on Unicode scalars | Identifies the SDK truthfully; Swift strings are Unicode |
| ISV token without tenant key / app ticket | logs, sends the request without `Authorization` | throws `LarkError.tokenUnavailable` | Fail fast instead of a guaranteed auth error from the server |
| WS fragment expiry | 10 s sweep timer | expired fragments are dropped whenever the next frame arrives | No background timer; same effective lifetime |
| Multipart file parts | `form-data` omits the filename for Buffers | file parts carry `filename` (`LarkFile.fileName`) | Required by some upload endpoints; harmless elsewhere |
| Channel: caller-supplied cards/posts | serialised in insertion key order | `JSONValue` → sorted keys | `JSONValue` objects are unordered; everything the channel builds itself is byte-identical |
| Channel: SSRF guard | pins the request to the validated IP; 50 MB cap enforced mid-stream | validates every resolved IP, the fetch re-resolves; cap checked after download; resolver injectable | `URLSession` cannot pin IPs without breaking TLS hostname checks |
| Channel: errors | axios error shapes; plain `Error` for an empty receive id | classified from `LarkError` (also business codes on HTTP 200); `LarkError.invalidArgument` | Swift error model |
| Channel: event handlers | some events fire-and-forget | handlers are `async throws` and awaited | Structured concurrency |
| Channel: webhook/agent options | `adapter`, `agent` | `dispatcher` / `handleWebhook(_:autoChallenge:)`, `webSocketConnector` | No Express/Koa or Node agents in Swift |
| Channel: types | loose JS values | `ChatInfo.memberCount: Int`, numeric-only `durationMs`, `content: String`, `normalize` throws `LarkChannelError(.unknown)` without a message | Swift types; node would hit a TypeError |
| gzip (addons encoding) | `zlib.gzipSync` | platform zlib (linked on Apple, `dlopen("libz.so.1")` on Linux), stored-block fallback if zlib is missing | Byte-identical output without a dependency |

## Layout

- `Sources/LarkCore` — runtime: client, token manager, HTTP, JSON, events, WSClient.
- `Sources/Lark<Module>` — generated API modules (+ optional hand-written helper files).
- `Sources/Lark` — umbrella module (`@_exported import` of everything), generated.
- `Tests/LarkCoreTests` — runtime tests (node-produced vectors, mock transports).
- `Tests/Lark<Module>Tests` — generated parity tests.
- `Tools/codegen` — `extract.js` (node-sdk → IR), `generate.js` (IR → Swift + tests + Package.swift).
- `Examples/` — runnable examples. `skills/` — agent skills for SDK users.

## Workflow

```bash
# Regenerate after updating node-sdk (all modules, or name some: ... im contact)
cd Tools/codegen && npm install
node extract.js <path-to-node-sdk> ir.json
node generate.js ir.json ../..
node status.js ir.json ../..      # refresh the coverage table in PLAN.md
cd ../.. && swift build && swift test
```

Before finishing any change: `swift build` (no warnings), `swift test` (all green),
PLAN.md and skills updated.
